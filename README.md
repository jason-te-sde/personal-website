# personal-website

Jason Te's portfolio. Next.js 16 (App Router) · TypeScript · Tailwind v4 · deployed on Vercel.

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # run this before every push — Vercel fails on things dev only warns about
npm run lint
```

## Routes

| Route | What |
| --- | --- |
| `/` | The whole 30-second read: hero, live Raft cluster, six projects, experience, stack, education |
| `/projects/keel` | The one deep case study |
| `/resume` | 307 → the resume PDF (see *Adding the resume* below) |

Everything is statically prerendered. There is no database, no API route and no contact form.

## Editing content

All copy lives in `content/` as typed TypeScript. **Nothing reads the resume JSON at build time**, on purpose:

- `profile.json` carries a phone number and a `needs_sponsorship` flag. Keeping it out of the build means a leak is structurally impossible rather than one spread operator away.
- Of 27 project entries in `experience_bank.json`, only ~7 are real; the rest are unbuilt blueprints generated by a planning skill. Any pipeline would need a whitelist, which is the curation already.
- The JSON strings are LaTeX-escaped (`\&`, `\%`, `$\rightarrow$`).

Two type-level guardrails worth keeping:

- `Stat.source` is **required** — a number cannot ship without the artifact that proves it.
- `Project.ownership` exists so team projects say what was and was not mine. PipeCI uses it, and its diagram dims the parts a teammate owned.

Bullets mark their one or two key terms with `**double asterisks**`; `components/rich-text.tsx` renders that. It is not Markdown and deliberately supports nothing else.

## Adding the resume

`profile.resumePath` is `null`, so every Resume button currently falls back to `mailto:`. The master PDF at `LinkedIn/resume/Jason_Te_Resume.pdf` still has `206-915-2538` in its text layer, and dropping that into `public/` would publish it to scrapers permanently.

To turn the resume on:

1. Put a phone-free PDF at `public/Jason_Te_Resume_Web.pdf`.
2. Set `resumePath: "/resume"` in `content/profile.ts`.
3. `grep -rI "915-2538" public/` — must return nothing.

Keep the filename date-free so the URL stays stable; replace the file to update it.

## Client components

Five, and that is the budget: `raft-cluster`, `typing-terminal`, `count-up`, `motion-fx`, all under `components/client/`. Everything else is a Server Component. If a sixth appears, something has gone wrong.

`raft-cluster` runs a real quorum calculation — crash three of five nodes and it stops electing and says `NO QUORUM`, because 3 is the quorum of 5.

## Things that will bite

- **Tailwind v4 has no `tailwind.config.ts`.** Tokens are in `app/globals.css` under `@theme`. Every tutorial you find shows v3; that config file does nothing here.
- **`eslint-config-next` 16 is not ESLint 10 ready** — its bundled `eslint-plugin-react` calls `context.getFilename()`, which ESLint 10 removed. ESLint is pinned to `9.x`. Do not route the config through `FlatCompat`; `eslint-config-next/core-web-vitals` already exports flat config.
- **TypeScript is pinned to `5.9.x`.** npm `latest` is 7.x, the native rewrite.
- **`turbopack.root` is pinned** in `next.config.ts` because this directory sits inside a parent git repo, so Next would otherwise resolve the wrong workspace root.
- **Filenames are kebab-case.** macOS is case-insensitive, Vercel's builder is not — `@/components/Hero` against `hero.tsx` builds locally and fails the deploy.
- **`<path>` inside a diagram needs `fill="none"`.** The parent `<g>` sets a fill, and an L-shaped path without it renders as a filled triangle.
- Amazon, LinkedIn, gRPC, WebSocket and ChromaDB have no Simple Icons mark. LinkedIn's is inlined in `components/section.tsx`; the rest render as text chips.
